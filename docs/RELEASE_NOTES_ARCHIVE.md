# Published release notes archive

## 0.8.0.0

## Пошук джерела відео

- Якщо штатний обробник не знаходить відео, застосунок пробує окремий резервний пошук MP4, HLS і DASH у даних сторінки, не змінюючи роботу підтримуваних сайтів.
- Знайдені джерела можна обрати у вікні застосунку. Браузерний пошук пропонується лише як запасний крок після невдалого автоматичного отримання відео, з поясненням дій. У темному приватному вікні підказка просить запустити плеєр, повідомляє про знайдене джерело й повертає до вибору відео. Кольори самих сайтів не змінюються.
- Браузер пошуку не має доступу до команд основного застосунку, не експортує cookies й не завантажує файли самостійно. DRM та обмеження доступу не обходяться; підтримка всіх сайтів не гарантується.
- Вибір знайденого джерела прив’язано до конкретної спроби: однакові посилання не плутаються між одиночним завантаженням і рядками черги. Новий пошук не успадковує старі тимчасові адреси.
- Після 15 хвилин браузер пояснює, що захищена сесія завершилася, та пропонує повернутися й почати пошук знову; застарілий вибір джерел прибирається.

## Надійність і обробка медіа

- Помилка перевірки завантаженого файла більше не запускає зайву конвертацію. Технічна причина перевірки зберігається у звіті історії без приватних шляхів; збій запуску перевірки не видається за пошкодження відео.
- Перевірка нових компонентів відокремлена від їх встановлення: за наявності робочих компонентів мережевий пошук не закриває форму завантаження.
- Невдалі перевірки отримують збережену паузу між спробами; ліміти GitHub враховуються до наступного дозволеного звернення.
- Сумісні відеопотоки можна перепакувати в MP4 без повторного кодування. Якщо несумісне лише аудіо, відео копіюється без зміни кадрів.
- Програмне кодування H.264 використовує ціль якості замість постійного заданого бітрейту; для PQ/HLG HDR перед конвертацією в сумісний SDR додано явну обробку кольорів.
- Допоміжні перевірки компонентів і медіафайлів обмежені за часом; скасування охоплює допоміжні процеси, а діагностичний вивід має обмежений розмір.
- Історія плейлистів зберігає окреме посилання й метадані кожного готового файла; повтор окремого запису не запускає всю початкову добірку.
- Після аварійного завершення можна явно видалити зареєстровані службові папки незавершених операцій. Автоматичного очищення користувацьких папок немає.
- Технічні подробиці та копіювання очищеної діагностики доступні в історії, без зайвої кнопки у вікні прогресу. Обмежений журнал для 20 останніх записів, включно з невдалими спробами без файла, зберігається локально після перезапуску; секретні заголовки, URL й особисті шляхи з пробілами приховуються.
- Збереження поточного прогресу черги відкладене, а важливі зміни стану зберігаються одразу.
- Перевірки папок, історії й VPN не виконуються в потоці вікна. Повторні перевірки незмінених компонентів використовують кеш; підписаний список оновлень може оновитися без перезапуску застосунку.
- Готові файли частково завантаженої добірки залишаються в історії після скасування або запиту входу. Брак місця під час конвертації та помилки авторизації призупиняють чергу.
- Повтор з історії чекає відновлення папки й усіх налаштувань: попередня чернетка посилання більше не може запуститися замість обраного запису.
- Скасування синхронізоване з повторними спробами й запуском FFmpeg. Фоновий процес не може стартувати після успішної зупинки; застосунок очікує остаточного завершення перед розблокуванням нової роботи.
- Тимчасова невдача апаратного кодування Windows більше не закріплює програмний режим на всю сесію; інші GPU-кодувальники залишаються доступними для наступних спроб.
- FFmpeg і FFprobe спочатку перевіряються в окремій службовій папці, потім встановлюються разом із позначками версії. Помилка заміни будь-якого файла запускає відкат комплекту зі збережених резервних копій.

## Перевірки та безпека

- Оновлено Tauri до 2.12.1, React до 19.3.0, Vite до 8.3.4 та сумісні плагіни; оновлено закріплені версії GitHub Actions.
- У Windows виправлено параметр WebRTC, який залишав прямий UDP-доступ у резервному браузері. Нативний тест із локальними TCP/UDP-приймачами підтверджує блокування після виправлення.
- Локальні перевірки та конвертація FFmpeg/FFprobe не відкривають вкладені мережеві джерела медіафайлів.
- Оновлено вразливі TLS- і тестові залежності; npm та Rust-аудити виконуються незалежно.
- Оновлено залежності Tauri для обробки URL: п'ять непідтримуваних Unicode-бібліотек замінено на ICU; додано перевірку, що запобігає їх поверненню.
- До перевірок PR додано тести й компіляцію для Windows та macOS без release-секретів.
- Додано інтерактивні тести інтерфейсу, перевірки резервного пошуку й контрольні сценарії обробки реальних медіафайлів.
- Завантажувач резервного пошуку перевіряє фактичні мережеві адреси під час отримання сторінки, перенаправлень і фрагментів потоку; локальні та службові адреси відхиляються.
- Вікно резервного браузера отримало окремий мережевий фільтр без зміни системного фаєрвола, проксі чи сертифікатів. Захист блокує локальні й службові адреси та обмежує альтернативні мережеві протоколи; у macOS додано нативні правила проти обходу через localhost. Пошук у браузері на Mac потребує macOS 26+, звичайне завантаження зберігає попередню сумісність. Це захист на рівні застосунку, а не системна мережева пісочниця.
- Прев’ю історії показуються лише з перевіреного локального кешу; прямі мережеві картинки в основному вікні заборонено.
- Перед завантаженням релізних файлів перевіряється відповідність наявного тегу коміту збірки; чернетка з іншим тегованим комітом не перезаписується.

- Windows-інсталяція знову використовує незмінну системну назву `yt-dlp BD`. Завдяки цьому автоматичний updater знаходить уже встановлену версію, замінює її в тому самому каталозі й не створює поруч другий застосунок.

- Видима назва у вікні застосунку та назви публічних release-файлів залишаються `Baldojnyi Downloader` / `BaldojnyiDownloader`.

## 0.7.0.0

- Керований yt-dlp перейшов на офіційний nightly-канал, який upstream рекомендує звичайним користувачам для своєчасної сумісності із сайтами. Застосунок перевіряє свіжу версію не частіше разу на добу, тому виправлення YouTube та інших платформ більше не залежать від нового релізу BaldojnyiDownloader.
- Стартова версія ядра, як і раніше, приходить через підписаний manifest релізу. Подальше оновлення приймається лише з точного офіційного шляху `yt-dlp/yt-dlp-nightly-builds`: GitHub SHA-256 має збігтися з upstream `SHA2-256SUMS`, а файл повторно перевіряється на диску до атомарної заміни.
- Додано захист від відкату на старішу nightly-версію, жорсткі межі розміру, перевірку `Content-Length` і timeout бездіяльності. Пошкоджена, надмірна або зависла відповідь не може нескінченно блокувати застосунок чи заповнювати диск.
- Попереднє робоче ядро зберігається при будь-якій помилці. Version/SHA metadata комітяться лише після успішної заміни executable, тому збій Windows rename не може залишити anti-rollback стан новішим за фактично встановлений файл. Нова версія запускається один раз із обмеженим часом перевірки до заміни.
- Застосунок працює в одному екземплярі, а runtime-папка додатково має міжпроцесне блокування. Друга копія не може оновлювати компоненти під час завантаження в першій.
- Щоденна перевірка більше не запускає важкий `yt-dlp --version` двічі. Уже актуальне ядро підтверджується одним API-запитом за accepted tag, кешованим перевіреним SHA-256, GitHub digest і локальним файлом — без повторного завантаження списку сум та довгого блокуючого вікна.
- Якщо фонове оновлення компонента не вдалося, біля нього одразу доступна кнопка повтору. Ручна й автоматична перевірки використовують один правильний 24-годинний timestamp.
- Відео `I5FsfhPhtT4`, яке на stable `2026.07.04` завершувалось помилкою 403, повністю завантажується й об’єднується на nightly.
- Офіційні macOS Apple Silicon та Windows x64 assets, SHA-256, Threads-плагін, production frontend, Rust-тести й Windows cross-target перевірки входять до релізної матриці.
