# Published release notes archive

This file preserves the exact user-facing bullets of published releases. Before
preparing the next release, append the just-published `RELEASE_NOTES.md` here.
The release test rejects exact bullet reuse so a maintenance change is not
silently attributed to multiple versions.

## 0.6.2.0

- Оновлено frontend-збірку до Vite 8 та сумісного React-плагіна. Для розробки й складання тепер використовується актуальна підтримувана версія Node.js.
- Production bundle явно орієнтується на Safari 15.4, тому заявлена підтримка macOS 12.3 не змінюється після переходу на Vite 8.
- Оновлено TypeScript до 5.9 та типи React/React DOM. Поведінка й інтерфейс застосунку не змінюються, але перевірка коду та сумісність майбутніх оновлень стали актуальнішими.
- Перевірки залежностей об’єднано в один щомісячний maintenance PR без автоматичних major-оновлень. Це прибирає десятки окремих бот-комітів і залишає великі міграції під ручним контролем.
- Збережено повний кросплатформний lock-файл, включно з optional-залежностями для Windows і macOS.
- Прогнано frontend-тести, release-перевірки, production build, Rust-перевірки та Windows cross-check перед підготовкою релізу.

## 0.6.3.0

- На macOS показ доступного місця враховує простір, який APFS може автоматично звільнити, але ніколи не показує менше за вже доступний фізичний обсяг. Захисна перевірка під час запису лишається консервативною.
- Системні смуги прокручування приховано на macOS і Windows; прокручування колесом, trackpad і клавіатурою працює як раніше.
- Пройдено 39 frontend-тестів, 22 release/Node-перевірки та 39 Rust-тестів.
- Пройдено production build, форматування, strict Clippy, перевірки macOS і Windows x64 та контрольну Tauri debug-збірку.

## 0.6.4.0

- Повторне підключення до YouTube більше не примушує yt-dlp використовувати застарілу комбінацію клієнтів, яка могла сама спричиняти повторні помилки 403. Після обриву застосунок заново отримує свіже посилання штатним способом поточної версії yt-dlp.
- Повідомлення під час другої спроби тепер точно пояснює, що застосунок повторно оновлює адресу потоку, а не перемикається на окремий несумісний режим.
- Додано автоматичну перевірку, що YouTube-повтори зберігають штатні аргументи yt-dlp і не підставляють застарілі клієнти.

## 0.7.0.0

- Керований yt-dlp перейшов на офіційний nightly-канал, який upstream рекомендує звичайним користувачам для своєчасної сумісності із сайтами. Застосунок перевіряє свіжу версію не частіше разу на добу, тому виправлення YouTube та інших платформ більше не залежать від нового релізу BaldojnyiDownloader.
- Стартова версія ядра, як і раніше, приходить через підписаний manifest релізу. Подальше оновлення приймається лише з точного офіційного шляху `yt-dlp/yt-dlp-nightly-builds`: GitHub SHA-256 має збігтися з upstream `SHA2-256SUMS`, а файл повторно перевіряється на диску до атомарної заміни.
- Додано захист від відкату на старішу nightly-версію, жорсткі межі розміру, перевірку `Content-Length` і timeout бездіяльності. Пошкоджена, надмірна або зависла відповідь не може нескінченно блокувати застосунок чи заповнювати диск.
- Попереднє робоче ядро зберігається при будь-якій помилці. Version/SHA metadata комітяться лише після успішної заміни executable, тому збій Windows rename не може залишити anti-rollback стан новішим за фактично встановлений файл. Нова версія запускається один раз із обмеженим часом перевірки до заміни.
- Застосунок працює в одному екземплярі, а runtime-папка додатково має міжпроцесне блокування. Друга копія не може оновлювати компоненти під час завантаження в першій.
- Щоденна перевірка більше не запускає важкий `yt-dlp --version` двічі. Уже актуальне ядро підтверджується одним API-запитом за accepted tag, кешованим перевіреним SHA-256, GitHub digest і локальним файлом — без повторного завантаження списку сум та довгого блокуючого вікна.
- Якщо фонове оновлення компонента не вдалося, біля нього одразу доступна кнопка повтору. Ручна й автоматична перевірки використовують один правильний 24-годинний timestamp.
- Відео `I5FsfhPhtT4`, яке на stable `2026.07.04` завершувалось помилкою 403, повністю завантажується й об’єднується на nightly.
- Офіційні macOS Apple Silicon та Windows x64 assets, SHA-256, Threads-плагін, production frontend, Rust-тести й Windows cross-target перевірки входять до релізної матриці.
