# BaldojnyiDownloader 0.6.1.0

## Покращено

- На Windows реальна конвертація тепер є остаточною перевіркою апаратного кодера. Застосунок пробує NVIDIA NVENC, Intel Quick Sync і AMD AMF у стабільному порядку, а до `H.264 software` переходить лише після фактичної відмови всіх доступних GPU-варіантів. Це прибирає хибний вибір software-кодування, коли короткий фоновий тест не встигав ініціалізувати драйвер.
- Перший реально успішний Windows-кодер запам’ятовується для наступних файлів, доки не зміниться FFmpeg. У popup завжди показується фактичний активний кодер: `NVENC`, `Quick Sync`, `AMF` або `H.264 software`.
- Якщо апаратний кодер відмовляє під час основної конвертації, застосунок прибирає лише власний тимчасовий MP4 і переходить до наступного варіанта без циклічних повторів. Завантажений вихідний файл зберігається, якщо всі спроби завершилися помилкою.

## Безпека та надійність оновлень

- Усі зовнішні GitHub Actions закріплені за незмінними повними commit SHA. Додано щотижневі npm/RustSec-аудити, CodeQL і Dependabot для npm, Cargo та GitHub Actions.
- yt-dlp, Deno та FFmpeg тепер встановлюються лише за підписаним runtime manifest. Він містить точні версії, HTTPS-джерела й SHA-256; пошкоджений, неповний або непідписаний manifest не замінить робочі компоненти.
- Застосунок зберігає останню прийняту версію та час генерації runtime manifest і відхиляє валідно підписаний, але старіший manifest. Чисте встановлення без попереднього стану залишається підтриманим.
- Windows FFmpeg спочатку перевіряється за офіційним upstream SHA-256, а потім додається до конкретного GitHub Release як незмінний versioned asset і повторно перевіряється застосунком перед установленням.
- Секрети Apple і Tauri updater доступні лише конкретним крокам підпису та нотаризації. Тимчасові `.p8`, certificate і signing keychain видаляються до перевірки артефактів та запуску зовнішнього upload action.
- Під час аудиту оновлено вразливу транзитивну npm-залежність; актуальний `npm audit` не знаходить відомих вразливостей.
