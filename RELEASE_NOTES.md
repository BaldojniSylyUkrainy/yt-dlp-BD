# BaldojnyiDownloader 0.6.0.0

## Нове

- На Windows застосунок тепер використовує апаратне H.264-кодування, коли сумісний GPU і драйвер справді можуть запустити кодер.
- Кодери перевіряються у стабільному порядку: NVIDIA NVENC, Intel Quick Sync, AMD AMF. Перевірка створює реальний короткий відеокадр, а не лише шукає назву кодера у списку FFmpeg.
- Під час конвертації застосунок показує фактичний активний кодер: `NVENC`, `Quick Sync`, `AMF` або `H.264 software`.
- Додано окрему підтримку відеодописів Threads: достатньо вставити звичайне посилання на допис із `threads.com` або `threads.net`, включно з короткими адресами `/share/...`. Якщо медіа доступне лише після входу, застосунок запропонує використати авторизацію з обраного браузера.
- Готові MP4 із Threads зберігаються напряму: застосунок не створює зайвий MKV, не запускає merge і не перекодовує вже сумісне відео. Для відеокаруселі після швидкої перевірки можна вибрати один ролик або всі відео.
- Готовий H.264/AAC MP4 тепер зберігається напряму незалежно від платформи — зокрема для TikTok, Instagram і Threads. Застосунок швидко перевіряє фактичні потоки через metadata або ffprobe; merge виконується лише коли yt-dlp справді завантажив окремі video/audio потоки, а перекодування — лише для несумісного контейнера чи кодека.

## Надійність

- Поле посилання на головному екрані тепер реагує миттєво й перевіряє лише формат HTTP/HTTPS. Застосунок більше не затримує старт попередньою мережевою перевіркою, яка могла помилково відхиляти Instagram, TikTok, Threads та інші підтримувані сервіси; реальну перевірку виконує yt-dlp після натискання «Завантажити», а результат показується у popup.
- Для Instagram застосунок тепер завантажує найкращий готовий сумісний MP4 одним файлом замість окремих VP9-відео й аудіо. Звичайні Reels більше не проходять зайві merge та конвертацію; максимальна якість з окремих потоків для YouTube та інших стрімових сервісів зберігається.
- TikTok тепер використовує окремий Android Chrome-профіль із комплекту yt-dlp замість мінливого desktop Chrome-профілю, який почав повертати 403. Safari прибрано з вибору cookies на macOS, бо система не дозволяє звичайному застосунку читати його базу; для повторної авторизації доступні Chrome, Firefox, Edge, Brave і Vivaldi.

- Якщо апаратний кодер відмовляє вже під час основної конвертації, застосунок автоматично прибирає лише власний тимчасовий MP4 та рівно один раз повторює обробку через `libx264`.
- Такий самий одноразовий програмний fallback тепер діє після реальної помилки VideoToolbox на macOS, а не лише після короткої перевірки кодера.
- Завантажений вихідний MKV не видаляється після невдалої апаратної спроби й залишається доступним, якщо не вдасться також програмна конвертація.
- Апаратна та програмна гілки зберігають однаковий сумісний результат: 8-bit `yuv420p` H.264-відео, AAC-LC-аудіо, контрольований bitrate, тег `avc1`, metadata mapping і fast start у MP4.
- Результат перевірки апаратного кодера кешується для поточної версії FFmpeg, тому пакетне завантаження не повторює до трьох hardware-probe перед кожним файлом.
- Прогрес, швидкість, ETA, скасування, зупинка дерева процесів і захист вільного місця працюють під час обох спроб без циклічних повторів.
- Проміжні потоки, фрагменти та `.part`-файли yt-dlp тепер ізольовані у власній тимчасовій папці кожного завантаження. Після помилки, скасування, повторної спроби або успіху вона прибирається, не зачіпаючи готові й сторонні файли.
- Threads-модуль постачається всередині застосунку, автоматично відновлюється у службовій папці й підключається лише як додатковий extractor до керованого yt-dlp. Для інших платформ поведінка завантаження не змінюється.
- Назви завантажень тепер мають безпечну байтову межу та зберігають ID матеріалу, тому довгі підписи Threads й інших платформ не можуть перевищити файловий ліміт macOS або Windows.
- Прибрано примусовий remux кожного відео в MKV. `--merge-output-format mkv` залишається лише страховкою для матеріалів з окремими потоками й, відповідно до поведінки yt-dlp, ігнорується для готового одиночного файла.

## Виправлено

- Повні TikTok video URL автоматично очищаються від tracking-параметрів перед перевіркою та завантаженням; TikTok-запити використовують сумісний із Chrome режим, а за потреби застосунок запропонує чинний вхід через браузер. Це працює і для одиночного, і для пакетного режиму.
- Ліві галочка та хрестик у фінальному вікні завантаження тепер закривають його так само, як кнопка справа.
- Windows installer та uninstaller явно використовують фірмову іконку, а фінальна дія інсталятора запускає `Baldojnyi Downloader` замість технічної назви `yt-dlp BD`.
- Локальний macOS release-build тепер відмовляється працювати не лише з незакоміченими tracked-змінами, а й з незатреканими файлами, щоб готовий застосунок точно відповідав Git-коміту.
